# Rendering shadow CVar batch H

This page covers the next 25 uncovered `r.Shadow.*` entries in alphabetical order after [shadow batch G](cvar-rendering-shadow-batch-g.md). The snapshot column records values from a community attachment with an unknown game build and capture method; these are observations, not verified Marvel Rivals defaults or recommendations. Exact-name Unreal Engine 5.9 reference entries provide upstream context only; they do not establish the game's engine fork or that the same renderer path is active.

The static scan targets Marvel Rivals Shipping build `1.1.4042190`. “Direct” counts are instruction-level references to a registry `ref_rva` CVar value address; “address-taken” counts are separate. For `var` entries, the scan does not supply a corresponding CVar value address, so zero `ref_rva` candidates is not evidence of no runtime use. Address-taking and registration/object references do not establish a read. These are static candidates, not control-flow traces.

## What the evidence establishes

Only `r.Shadow.Virtual.NonNaniteVSM` has a direct value-address comparison in this set: three direct comparison candidates and one address-taking reference. The other 24 entries are registered as `var`; the saved scanner does not provide their CVar value address in the `ref_rva` field, so they cannot be categorized as direct value reads from that scan. Some object-address candidates exist, but these can reflect registration or address handling and are not read evidence. Indirect use and uses outside the scanned binaries may be missed.

No controlled `.ini` override, live CVar query, or in-game shadow comparison was performed for this batch. `var`/`ref` classification, help text, a UE 5.9 match, snapshot value, or static instruction candidate does not prove that the supplied loader accepts an override, that it wins over subsequent setup, or that the setting changes a live match. Consult [CVar overrides](cvar-overrides.md) for the loader-specific evidence and limits.
