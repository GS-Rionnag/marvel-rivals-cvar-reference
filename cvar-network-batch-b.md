# Network CVar batch B

This page covers 25 exact `net.*` names from the community `var`/`ref` registry. The registry and value snapshot do not identify their game build or capture procedure. Captured values are not assumed to be defaults. Local code evidence comes from direct RIP-relative references in the installed Marvel Rivals Shipping executable `1.1.4042190`; a reference is not proof that a setting accepts a loader override or that its path runs in normal play.

## What this evidence supports

- Fourteen of the 25 names have direct read/comparison candidates at their `ref_rva` in the local executable. The remaining entries had no direct value-read candidate in the saved scan. `obj_rva` address-taking and pointer-write rows are registration/setup leads, not CVar value reads.
- Fifteen names have exact-name entries in Epic's UE 5.9 reference. Those defaults are included for upstream context only. The community registry's capture build and the present game's engine revision are unknown, so Epic defaults are not Marvel defaults.
- The `CVarDump.txt` values are a captured community snapshot, not confirmed game defaults. `net.DeleteObjLock` is absent from that snapshot.
- The loader's `[Overrides]` syntax can express `name=value`; this page contains no runtime test proving that the game accepts or retains any of these settings. For the distinction between loader syntax, runtime acceptance, local code reads, and controlled behavior, see [CVar override evidence levels](cvar-overrides.md#does-a-cvar-actually-change-in-marvel-rivals). Official Marvel Rivals notices about mods/config changes and the risks of runtime injection are summarized in [CVar overrides](cvar-overrides.md#current-marvel-rivals-policy-on-injected-mods-and-config-changes).
