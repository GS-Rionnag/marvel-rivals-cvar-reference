# Rendering shadow CVar batch G

This page covers the next 25 uncovered `r.Shadow.*` entries in alphabetical order after [shadow batch F](cvar-rendering-shadow-batch-f.md). The snapshot column records values from a community attachment with an unknown game build and capture method; these are observations, not verified Marvel Rivals defaults or recommendations. An exact-name Unreal Engine 5.9 reference is upstream context only and does not show that this game uses the same implementation or renderer path.

The static scan targets Marvel Rivals Shipping build `1.1.4042190`. “Direct” counts are instruction-level references to the registry's `ref_rva` CVar value address; “address-taken” counts are separate. Neither count is a complete control-flow trace or proof that the setting is active in a match.

## Evidence and limits

All 25 names have a `var` or `ref` row in the preserved community registry and a corresponding snapshot entry. The saved build scan has at least two direct value-access candidates and one address-taken reference for each name. These instruction matches show that code references the registered value address in the scanned build; they do not establish which branch consumes it, whether that branch runs during a match, or whether an override can reach the value. UE 5.9 descriptions are exact-name reference matches only; they may describe upstream behavior that differs from the shipped game.

No controlled `.ini` override, live console query, or in-game comparison was performed for this batch. In particular, presence in a registry, a snapshot value, and a static read candidate do not prove startup `.ini` editability, override precedence, or visible effect. Treat the snapshot values as observations, not as defaults or a preset. See [CVar override notes](cvar-overrides.md) for loader and runtime limits, and the [community CVar registry](cvar-community-registry.md) for source data and capture caveats.
