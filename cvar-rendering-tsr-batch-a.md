# TSR rendering CVar batch A

This guide documents the first 25 uncovered registered `r.TSR.*` variables in source-registry order. It covers TSR scheduling/history, reactive masks, shading rejection, subpixel reprojection, and velocity-based history weighting. Community help, exact-name Epic UE 5.9 references, and captured snapshot values are reported separately. The registry does not identify the game build or capture method; upstream references do not establish Marvel Rivals engine version or runtime behavior.

Build evidence comes from static address-reference scanning of Marvel Rivals Shipping build `1.1.4042190`. All entries in this batch are registered as `var` in the supplied registry and have no `ref_rva`; matches are CVar-object setup/address candidates, not proof that the game reads an overridden value. No `.ini` override, live CVar query, instruction-level use trace, or gameplay A/B was performed.

## Snapshot and editability caveats

- The community snapshot differs from the Epic UE 5.9 reference default for four rows in this batch: `r.TSR.History.ScreenPercentage` (100 vs 200), `r.TSR.History.UpdateQuality` (2 vs 3), `r.TSR.RejectionAntiAliasingQuality` (1 vs 2), and `r.TSR.ShadingRejection.Flickering.Period` (3 vs 2). These are source differences, not evidence of recommended values.
- Some variables have community help but no exact-name Epic 5.9 default match; those show `—` in the upstream-default column.
- Descriptions explain intended TSR behavior, but do not prove the game uses the same implementation or that the loader accepts overrides. Static addresses in this batch are object setup references only.
- `r.TSR.WaveOps` is the one remaining uncovered name in this registry family and is reserved for a follow-up guide.

For the complete candidate inventory, see the [community CVar registry](cvar-community-registry.md); build scan scope is summarized by the [build-specific static-analysis notes](EVIDENCE.md#build-specific-static-analysis).
