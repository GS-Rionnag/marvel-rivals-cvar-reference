# Ray-tracing geometry and global-illumination CVars: batch A

This page documents the next 25 uncovered `r.RayTracing.*` variable rows in the community registry. The first three concern static-mesh world-position offset (WPO) evaluation; the rest concern the ray-traced global-illumination and final-gather controls. The supplied registry gives no exact Epic Unreal Engine 5.9 reference match for the 22 global-illumination rows. Their meanings below therefore follow the registry help only; no parallel upstream definition is inferred.

The `CVarDump.txt` values are an attachment snapshot with unknown game build and capture method. They are observations, not verified Marvel Rivals defaults or recommendations. In particular, `r.RayTracing.GlobalIllumination.FinalGather.NormalRejectionKernel` is captured as `0.2`, while its help states `1.0e-2`; neither value is established as the live default.

## What the build scan establishes

The community registry classifies four entries as `ref` and the remaining 21 as `var`. In the saved scan of Marvel Rivals Shipping build `1.1.4042190`, direct `ref_rva` value-access candidates were found only for `Denoiser`, `DiffuseThreshold`, `EvalSkyLight`, and `FinalGather.Distance`. The other entries have no `ref_rva` in the registry, so this scan cannot identify a direct read of their registered value; `obj_rva` setup references are not evidence of a value consumer. The four access sites do not by themselves identify a full control-flow path or prove that ray tracing is enabled in a match.

The `r.RayTracing.*` prefix, registry help, and captured values do not establish that Marvel Rivals' ray-tracing path is enabled on a given system. Nor do they prove that a startup `.ini` override is accepted, survives later config layers, or changes a live session. No controlled override, runtime console query, or in-game image comparison was performed for these settings.
