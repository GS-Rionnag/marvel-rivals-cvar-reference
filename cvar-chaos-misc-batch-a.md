# Miscellaneous Chaos CVars, batch A

This page records 25 `p.Chaos`/`p.chaos` registry entries that do not belong to the larger documented solver, collision, or geometry-collection groups. Exact spelling and capitalization are kept from the community registry.

## Evidence and editability limits

The source is the preserved Discord community `console_vars.tsv`, `console_objects.tsv`, and `CVarDump.txt`; their capture build and method are not known. The captured values below are not defaults. The help strings are reproduced as supplied, including apparent mismatches. The local binary evidence is from Marvel Rivals Shipping build `1.1.4042190` and the saved `.text` address-reference scan; its method and limits are described in [the source notes](EVIDENCE.md#build-specific-static-analysis).

The example loader instructions say that uncommented `name=value` lines under `[Overrides]` merge over config, and that `!name=` removes the configured value. That proves the loader has syntax for expressing a setting; it does **not** prove that the game registers this exact name in this build, accepts a value, preserves it after startup, or reaches code that uses the value in normal play. The community registry and the scan provide static evidence only. No controlled in-game override was tested for this batch.

In the table, “scanner candidates” count direct-memory candidates matching the community `ref_rva` plus any address-taking candidates; they are not all semantic reads. The “local evidence” column only describes observed code instructions and conservative implications. The references do not by themselves establish that the registry attachment and installed executable share a build.

## What this says about changing the settings

Every row above can be written syntactically as `ExactName=value` under the loader's `[Overrides]` section. The `var`/`ref` tags are from the community attachment, not a runtime acceptance test. A static branch or load in the installed executable is evidence the value is referenced in some code, but it does not establish that configuration parsing accepts the override, that the value is not later reset, or that the branch is reached during a match. Entries whose only matched instructions are initialization stores (`AllowCreatePhysxBodies`, `AutoLink.LinkHitByAbilityOnly`) have even weaker evidence of active use. Runtime editability and gameplay results should remain **unverified** until tested against this exact game build with a controlled one-variable comparison.
