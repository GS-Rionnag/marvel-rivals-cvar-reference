# Rendering shadow CVar batch D

This page covers the next 25 uncovered `r.Shadow.*` variable rows in the supplied community registry. The `CVarDump.txt` values are observations from an attachment with unknown build and capture method, not verified game defaults or recommendations. Exact-name UE 5.9 matches provide upstream context only; Marvel Rivals uses a fork, and matching help does not prove that the corresponding renderer path is active.

The local scan targets Marvel Rivals Shipping build `1.1.4042190`. A direct-memory candidate means an instruction accesses the registered value address. It is static evidence, not a full control-flow trace, a test of visible results, or proof that a startup `.ini` override works. `var` rows lack a `ref_rva` value address in this registry, so object/setup matches cannot be counted as direct value reads.

## What the scan establishes about overrides

Five of the 25 rows have direct `ref_rva` value-access candidates in the scanned build: `r.Shadow.MinDirectionalLightAngleForRTHF`, `r.Shadow.OcclusionCullCascadedShadowMaps`, `r.Shadow.OnlyDistanceFieldShadowByLightChannels`, `r.Shadow.PerObjectProjectionScissor`, and `r.Shadow.PointLight.MaskBoxAsScreenRadius`. Three other `ref` entries have address-taking references only; they do not establish a read of the stored value. The `var` entries have no corresponding `ref_rva` value access in this scan. Indirect accesses and paths outside the scanned executable can be missed.

None of these static observations proves that a local startup `.ini` override is accepted, wins over later config layers, or changes a live frame. No controlled override, console query, or in-game shadow comparison was performed. Snapshot values must not be copied as recommended settings.
