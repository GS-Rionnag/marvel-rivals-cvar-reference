# Ray tracing CVar notes: batch A

This page records the 25 exact names assigned to this batch. The meanings below come from the captured community CVar help in [`console_vars.tsv`](https://discord.com/channels/1512820805615091712/1512825591529869383/1570970983353950322); values in the table are the captured [`CVarDump.txt`](https://discord.com/channels/1512820805615091712/1512825591529869383/1562934699502866452) snapshot, not asserted defaults. The registry's source build/capture method is not established, so treat that snapshot as an observed configuration only. Where help states a default, it is identified as such. `int32` and `float` are the captured registry types.

## Evidence limits and using overrides

The shipped-build address scan is static triage for Marvel Rivals build `1.1.4042190`; see [build-specific static-analysis notes](EVIDENCE.md#build-specific-static-analysis) and [community research-source notes](EVIDENCE.md#community-sources). An address-taking reference (`obj_rva`) establishes an address was used, often during registration/setup, not that the setting is read. A direct-memory candidate (`ref_rva`) establishes machine code accessed the CVar object's storage, but by itself does not prove the branch runs in a normal match or that the corresponding feature is active. This scan found direct-memory candidates for only six of the 25 settings: `AmbientOcclusion`, `AmbientOcclusion.SamplesPerPixel`, `CompileMaterialAHS`, `CompileMaterialCHS`, `DebugDisableTriangleCull`, and `DebugForceOpaque`. The other 19 had no `ref_rva` candidate in this scan; that absence is not proof of dead code. These are renderer/ray-tracing controls, and the local evidence does not establish that Marvel Rivals enables the underlying ray-tracing path on a given system.

An entry can be written as `name=value` beneath `[Overrides]` in the mod loader's INI syntax described in the loader guide. That documents only how to express an override. The CVar snapshot, community help, and static references do not establish that the loader accepts a particular line, that the game registers or honors it at runtime, or what effect it has in a live session. No runtime override was tested for this batch. UE 5.9 documentation/source, when consulted, is context for likely engine semantics only; it does not prove Marvel Rivals uses that exact engine implementation.

## Reading the findings

The help text is the strongest available source for the meanings above, but it is community-captured engine metadata and may not describe the game's active configuration. Values are copied from one snapshot and are not a recommendation. The six direct-memory-reference entries have stronger local static evidence that code consults their stored values; the scan does not identify a reliable in-game call path or prove the ray-tracing feature is active. For the remaining entries, only their registry/address-taking presence and captured help/value are established. In particular, compile controls may affect shader permutations or build/startup work, while debug/culling settings may only matter in renderer modes that the game exposes; those implications are not runtime-verified here.
