# Lumen CVar batch E: Screen Probe Gather tracing and integration

This guide covers the next 25 uncovered registered `r.Lumen.*` variables in name order after [batch D](cvar-rendering-lumen-batch-d.md). Meanings below come from the community registry help, with an exact-name Unreal Engine 5.9 reference used only as upstream context. The registry and snapshot do not identify a capture build or procedure, and this guide does not establish that Marvel Rivals uses the same upstream implementation or activates each path.

The build scan examined Marvel Rivals Shipping build `1.1.4042190`. A direct-memory candidate means a static instruction targets the registered `ref_rva`; it does not prove the instruction is on an active match path, and no candidate does not prove a setting is unused. `var` rows with no `ref_rva` do not receive a direct-value scan result. No controlled `.ini` override or in-game effect test was performed.

## Evidence and editability limits

- The 25 entries split into 17 `ref` rows with at least one direct-memory candidate and eight `var` rows without one. This scan is static triage: it does not demonstrate that a renderer path is selected in a live match.
- The community snapshot values are captured values, not verified Marvel Rivals defaults or recommendations. The UE 5.9 default column is published upstream reference data, not proof of the game's engine revision or fork behavior.
- The names cover hair tracing, hardware ray tracing, importance sampling, and Screen Probe integration. Whether these features are available depends on game configuration, platform capabilities, renderer choices, and runtime path selection; those conditions were not tested here.
- No `.ini` editability test was run. A registry row or a direct value access alone does not show that a loader accepts an override, that the CVar is writable, or that changing it affects a match.
