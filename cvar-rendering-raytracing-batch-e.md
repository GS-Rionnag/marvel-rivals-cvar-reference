# Ray tracing CVar notes: batch E

This page records the next 25 uncovered `r.RayTracing.*` variables alphabetically after [ray-tracing batch D](cvar-rendering-raytracing-batch-d.md), excluding names already documented in focused ray-tracing guides. It uses the preserved community registry, its separate `CVarDump.txt` snapshot, the address scan of Marvel Rivals Shipping build `1.1.4042190`, and exact-name entries in Epic's Unreal Engine 5.9 CVar reference. The community attachments do not identify their game build or capture method. Snapshot values are observations, not verified game defaults or recommendations.

The prefix and registration do not prove that a ray-tracing feature is enabled or reached in a live match. Likewise, static references do not prove that a startup `.ini` override is accepted or changes the rendered result. These settings matter only if the relevant renderer path is supported, selected, and executed.

## What the build scan establishes

The registry classifies nine entries in this batch as `ref` and 16 as `var`. The saved scan has direct-memory candidates for the eight `ref` values listed in the table. These are static instruction candidates in Shipping build `1.1.4042190`; they do not show that the related branch executes in a match, that ray-traced reflections are selected, or that changing the value affects the image. For the 16 `var` entries, the scan found object/setup references but no direct value-read candidate for the registered value. Object address-taking or registration-related hits are not evidence that a modified value is consumed. The scanner targets direct RIP-relative references and can miss indirect access patterns.

Only the first three CVars have exact-name entries in Epic's Unreal Engine 5.9 reference. Their upstream defaults and descriptions appear in the table; those entries do not identify Marvel Rivals' engine revision or establish the game's behavior. The other 22 entries have no exact-name reference in the supplied UE 5.9 catalog. Registry help remains community-provided description, not verified source implementation. The `TemporalWeight` help/snapshot mismatch is recorded rather than resolved by assumption.

No live console query, controlled `.ini` override, or in-game A/B test was performed. Presence in the registry or a static access candidate does not establish that a CVar is editable through the supplied mod loader, that an override survives later config layers, or that a relevant rendering path is active.
