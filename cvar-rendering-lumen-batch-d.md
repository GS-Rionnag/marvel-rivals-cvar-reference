# Lumen CVar batch D: reflections and screen probes

This guide covers the next 25 uncovered registered `r.Lumen.*` variables in name order. The community registry and its snapshot have no stated capture build or method. Exact-name matches to Epic's Unreal Engine 5.9 reference are upstream context, not proof that Marvel Rivals uses the same engine implementation or enables each rendering path.

The build evidence below comes from a static address scan of Marvel Rivals Shipping build `1.1.4042190`. For all 18 `ref` entries in this batch, the scan found at least one direct-memory candidate targeting the CVar value address. Those are static accesses, not full control-flow traces. The seven `var` entries have object/setup evidence only in this scan. Neither kind proves a startup `.ini` override is accepted or that a changed value affects a live match.

## Evidence and editability limits

- Of the 25 entries, 18 are `ref` rows with at least one direct value-access candidate in the build scan. The remaining seven are `var` entries with setup/address evidence only. A direct read is not proof that a branch runs in a match or that configuration can change the value.
- Twenty entries have exact-name matches in the UE 5.9 reference. Five do not: `r.Lumen.RuntimeSupport`, `r.Lumen.ScreenProbeGather.ClearRenderTargetsBeforeDownsampleIntegrate`, `.Debug`, `.Debug.ProbePlacement`, and `.FixedStateFrameIndex`. UE reference matches are upstream context, not proof of Marvel Rivals' engine version or defaults.
- Community snapshot values are observations from an attachment with unknown build and collection method. They are not recommendations or verified live defaults.
- No controlled `.ini` override, live console query, renderer-capability check, or in-game visual comparison was performed. Screen Probe and reflection settings are conditional on the corresponding Lumen path being selected and supported.
