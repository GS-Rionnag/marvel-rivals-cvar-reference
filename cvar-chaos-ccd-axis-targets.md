# Chaos CCD axis thresholds and target selection CVars

This guide covers the nine `p.Chaos.CCD.*` variables from the supplied community registry. It is separate from [the six `p.Chaos.Collision.CCD.*` controls](cvar-chaos-ccd.md). The notes combine registry help and captured values with direct-reference evidence in Marvel Rivals Shipping build `1.1.4042190`. Snapshot values are not verified defaults or recommended overrides.

| CVar | Type | Snapshot | Meaning and local-build evidence |
| --- | --- | ---: | --- |
| `p.Chaos.CCD.AllowedDepthBoundsScale` | float | `0.2` | When rolling back to time of impact (TOI), allow penetration up to the smallest bound extent multiplied by this scale, rather than requiring zero penetration, per help. At `0x14282B52D` the executable multiplies a computed extent by the CVar and stores the scaled result in a local settings field; another read/comparison is at `0x1426A30EF`. The complete rollback decision is not reconstructed. |
| `p.Chaos.CCD.AxisThresholdMode` | int32 | `2` | Selects how axis-threshold bounds are derived from particle geometry. Registry help defines `0` as object bounds; `1` as the thinnest object-bound axis reused for all CCD axes; `2` as the thinnest shape bound on each axis; and `3` as the thinnest shape-bound axis reused for all axes. Reads at `0x14288315D`, `0x14288333B`, `0x1428CDD81`, and `0x1428CDF5E` feed mode branches. The local mode-1 branch writes the same minimum bound to each axis (`0x1428831BF`–`0x14288321B`); the other modes' full geometry flow is not traced here. |
| `p.Chaos.CCD.CCDAxisThresholdUsesProbeShapes` | bool | `false` | When true, probe shapes participate in CCD-axis-threshold computation and can generate contacts in the initial CCD phase, per help. Read at `0x1428832AF` and `0x1428CDEE1`; the first path branches on the value while iterating shape data. |
| `p.Chaos.CCD.CCDSweepsUseProbeShapes` | bool | `false` | Help says true allows probe shapes to be swept for more accurate collision detection. The local build contains the registered name, but the saved direct-reference scan has no matching memory-read candidate; this behavior is not independently confirmed from the executable trace. |
| `p.Chaos.CCD.EnableThresholdBoundsScale` | float | `0.4` | CCD eligibility is based on position change exceeding the smallest bound extent times this scale. Help says `0` always uses CCD and values below `0` disable it. Code at `0x1426A5E67` returns false for negative values, true for zero, and otherwise continues with the bounds/threshold calculation; `0x14282B51D` multiplies a computed extent by the scale. This matches the stated gate. |
| `p.Chaos.CCD.NewTargetDepthMode` | bool | `true` | Help says to find the first contact with penetration equal to `AllowedDepthBoundsScale * Size`, instead of the first contact without that penetration condition. The value is read at 60 direct sites in the scan, including a branch at `0x1428AA253`. The branch is present in multiple sweep routines; the complete first-contact search behavior is not reconstructed. |
| `p.Chaos.CCD.NoCullAllShapePairs` | bool | `true` | Controls early phi-based contact culling for sweeps across all shape pairs, not just convex-convex, per help. In one sweep path the value is read at `0x1427E7967`; nonzero branches around a subsequent floating-point comparison and flag-setting block at `0x1427E79BB`–`0x1427E79E0`. Other pair-specialized paths read the same value at `0x1427E7A26`, `0x1427E7AA5`, `0x1427E7B30`, `0x1427E7BAF`, `0x1427E7C39`, and `0x1427E7CB7`. |
| `p.Chaos.CCD.OnlyConsiderDynamicStatic` | int32 | `0` | Help says CCD is only enabled for dynamic-static pairs. At `0x1427E680F`, a nonpositive value skips the following type-filter path; positive values reach pair-state checks. The full type encoding and all downstream pair outcomes are not identified. |
| `p.Chaos.CCD.UseGenericSweptConvexConstraints` | int32 | `1` | Help says this selects generic swept-convex constraint generation for convex pairs without specialized implementations. The local build contains the registered value address, but the saved direct-reference scan found no matching memory-read candidate; runtime use is not independently confirmed here. |

## Evidence and limits

- Names, types, help, and reference addresses come from [`console_vars.tsv`](https://discord.com/channels/1512820805615091712/1512825591529869383/1570970983353950322); the values above come from [`CVarDump.txt`](https://discord.com/channels/1512820805615091712/1512825591529869383/1562934699502866452). The [source manifest](EVIDENCE.md#build-specific-static-analysis) records the Discord attachments' exact match to these preserved files.
- Direct-reference candidates and scan limits are recorded in [`build-4042190-cvar-address-hits.tsv`](EVIDENCE.md#evidence-artifacts-not-included). Instruction-level notes above were checked against the local executable disassembly. A missing direct read does not prove that a value is unused; indirect and non-RIP-relative accesses can be missed.
- No controlled in-game overrides were tested. Do not treat snapshot values as defaults or safe tuning ranges.
