# Nanite CVar batch D

This guide records the final 24 currently uncovered registered `r.Nanite.*` names after batches A–C, recomputed from the latest public documentation tables. It closes the currently known `r.Nanite.*` family among the supplied 8,973 unique `var`/`ref` registry names; this is not a claim that the registry contains every engine or game CVar. The source attachment does not identify its capture build or method. Snapshot values are taken from `CVarDump.txt` and cross-checked against the generated catalog when present. Epic UE 5.9 defaults and descriptions are exact-name upstream references, not confirmed Marvel Rivals defaults.

Build evidence is from static address-reference scanning of Marvel Rivals Shipping build `1.1.4042190`. `direct-memory` matches may be reads, writes, comparisons, or initialization; `address-taken` matches show address use only. Counts do not establish complete call flow or executed paths. No controlled startup override or in-game render test was performed.

## Interpretation limits

- The streaming controls name asynchronous scheduling, debug request views, allocation growth, and paging limits. These labels and supplied help do not establish which path is used by the game or the effect of changing it.
- Help for view-mesh LOD bias, VSM invalidation, and visualization modes identifies intended engine controls, not a tested quality or performance result in Marvel Rivals.
- The community help for `r.Nanite.UseSceneInstanceHierarchy` contains an apparent source typo; the exact-name Epic 5.9 reference describes the scene-instance culling hierarchy. This upstream wording is not proof that Marvel Rivals uses the same implementation.
- Empty community help remains unresolved unless an exact upstream description exists; upstream text is explicitly labeled.
- `var`/`ref` registration, a snapshot, and address-scan hits do not establish `.ini` override acceptance or an in-game effect. Snapshot values are not recommendations.
