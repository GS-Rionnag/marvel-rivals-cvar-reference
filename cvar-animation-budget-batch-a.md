# Skeletal-mesh animation budget CVars

This guide covers 22 `a.Budget.*` controls documented in the community CVar registry. Together, the help text describes Unreal's skeletal-mesh batching/budget scheduler: it estimates component tick work, compares it with a millisecond budget, then adjusts ticking, interpolation, and reduced-work states according to significance and pressure. These meanings come from registry help; the saved scan shows local value-access candidates, but this guide does not reconstruct each consuming branch or test visual output.

The snapshot values below are from a separate attachment with unknown build and collection method. They are observations, not verified defaults. In particular, `BudgetMs` is captured as `1` while its registry help states a default of `3.0`, and `AutoCalculatedSignificanceMaxDistance` is captured as `30000` while its help states `300.0`. This mismatch means the dump should not be treated as a canonical default set.

## How the controls fit together

The help text groups these settings into a feedback system. `BudgetMs` defines the allocated skeletal-mesh tick time. Work estimates are initialized by `InitialEstimatedWorkUnitTime` and then updated from measured work, with `WorkUnitSmoothingSpeed` governing convergence. `BudgetPressureSmoothingSpeed`, the normal and aggressive reduced-work factors, and `BudgetFactorBeforeReducedWorkEpsilon` describe how the scheduler reacts to sustained pressure and avoids rapid state flapping.

When work exceeds budget, the help describes limiting or amortizing updates through offscreen tick limits, interpolation, significance, and reduced-work transitions. `MinQuality` and `MaxTickRate` explicitly allow quality choices to exceed the time budget. Exact ordering, formulas, clamping, and the precedence between these controls were not traced in this research.

## What this proves about editability

All 22 registry rows are typed `ref`, and the build scan contains multiple direct-memory candidates targeting every corresponding reference. That is evidence the installed binary has code paths that access these values. It does not prove a local startup `.ini` override is accepted, that changing a value is safe, or that the resulting behavior is visible in a given match. No controlled config comparison or live-game test was performed.

The `a.Budget.Enabled` help specifically warns that it should be set only when no skeletal meshes are running. If experimenting, use startup configuration, make one change at a time, retain a rollback copy, and compare the same character/scene. Avoid toggling this enable switch while gameplay meshes are active.
