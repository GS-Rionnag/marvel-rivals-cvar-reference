# Ray tracing CVar notes: batch D

This page documents the next 25 uncovered `r.RayTracing.*` entries alphabetically after the earlier ray-tracing geometry and ray-traced GI guides. The source is the community `console_vars.tsv` registry plus its separate `CVarDump.txt` snapshot, the address scan of Marvel Rivals Shipping build `1.1.4042190`, and exact-name matches (where present) in Epic's published Unreal Engine 5.9 CVar reference. The community attachment does not identify its game build or capture method. Snapshot values are observations, not verified defaults or recommendations.

A CVar's registration/name, an address-taking hit, or a direct static read does not prove that the ray-tracing path is active in a match. It also does not prove a startup `.ini` override is accepted, wins at runtime, or changes rendered output. These controls matter only when their corresponding renderer path is selected and supported.

## What the evidence establishes

The saved registry classifies four entries here as `var` (`MaxLightCount`, light-culling `CellSize` and `Cells`, and `LightFunction`) and the other 21 as `ref`. The address scan has `ref_rva` direct-memory candidates for those 21 `ref` entries. Those instructions show static value access in the scanned executable, but do not by themselves prove that the associated code path executes, that the renderer is using hardware ray tracing, or that any value has a visible effect. For the four `var` entries, `obj_rva` address/setup hits are not direct value reads. The scan is limited to direct RIP-relative matches and can miss indirect accesses.

Fourteen of these entries have exact-name matches in the Epic UE 5.9 reference; eleven do not. The row-level match status is shown in the tables. An exact upstream match provides engine-reference context only and does not establish that Marvel Rivals uses that version. UE 5.9 descriptions/defaults are version context, not proof that Marvel Rivals uses the same implementation. The `MaxLightCount` community help appears mismatched to its name, so it remains unresolved despite the captured value.

No live console query, controlled `.ini` override, or in-game A/B test was performed for these entries. A row in the registry or snapshot cannot establish editability. Even for `ref` rows with static reads, whether an override works depends on config loading and whether the relevant ray-tracing/Nanite path is enabled and reached.
