# Epic CVar reference entries found in the game binaries but absent from the community variable registry

These names match Epic's Unreal Engine 5.9 CVar reference exactly and were found as printable strings in the local build scan, but they have no `var` or `ref` row in `console_vars.tsv`. This supports their meaning as engine CVar names and their presence in the scanned binary set; it does not prove that Marvel Rivals registers or honors them at runtime. Entries also present in `CVarDump.txt` are marked with their snapshot value.

- Engine source: [Epic Unreal Engine 5.9 Console Variables Reference](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-console-variables-reference).
- Local scan: build `1.1.4042190`, 126 executables/DLLs; see [full inventory](EVIDENCE.md#build-specific-static-analysis).
- Exact-name entries: 49; also in the community value snapshot: 21; not in that snapshot: 28.

## Cross-source example: `r.Lumen.Visualize.ViewMode`

This exact name appears in the community console-object table with flags `1` and a help list of five modes: `Overview`, `LumenScene`, `GeometryNormals`, `ReflectionView`, and `SurfaceCache`. The exact Epic UE 5.9 reference entry lists those modes plus `PerformanceOverview` and `DedicatedReflectionRays`. The local 1.1.4042190 inventory finds the literal name in both x64 and ARM64EC Shipping executables. It has no `var`/`ref` row in the community registry and no value in the community snapshot.

This is an evidence intersection, not evidence that the game registers the name or accepts a config override. The two extra modes in Epic’s reference could reflect engine-version differences, build-specific help text, or differences in the community attachment; the available evidence does not resolve which explanation is correct. The community object flag is reproduced as metadata and is not interpreted here as a known mutability or priority level.
