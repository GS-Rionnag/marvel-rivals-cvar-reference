# M2215 CVar batch B: AOI and movement-thread controls

This guide records 15 currently uncovered, exact-case `M2215.*` registry entries. The supplied help describes AOI replication policy, RPC filtering, pooled-actor handling, log verbosity, and an experimental packed-movement worker path. The registry does not identify its capture build; none of these names has a captured value or an exact-name Epic UE 5.9 entry.

Translations of Chinese help are assistant renderings marked unreviewed. The local build scan matches instructions to the registry's `ref_rva` and `obj_rva`; it does not establish a value read, execution, startup override acceptance, or in-game behavior. Most entries have only one `ref_rva` direct-memory candidate plus one address-taking match and three `obj_rva` direct-memory candidates plus one address-taking match; per-row exceptions are called out.

## Interpretation limits

- AOI means Area of Interest in the supplied help. The `Enable` and distance descriptions indicate BattleRule fallbacks and overrides, but do not establish which rules, actor classes, server/client endpoints, or valid distance ranges are active in the installed build.
- `BlockServerRPC` only describes RPCs already wired into the filter; it does not imply that every RPC is blocked. No behavior or safety testing was performed.
- The PendingMoveThread help explicitly distinguishes shadow comparison from the experimental commit path. It does not show that either mode is safe to enable in public matches or that this loader's `.ini` mechanism can change it.
- Snapshot values are absent for this family. The help's described defaults are not evidence of runtime defaults in the installed build.
- Static reference candidates are not proof of CVar value reads or writes. Address-taking matches can be registration or another pointer use; the scan did not trace these candidates through complete runtime call paths.
