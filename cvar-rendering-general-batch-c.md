# Rendering and game-specific CVar batch C

This guide covers 25 exact `var`/`ref` entries from the preserved community registry that did not have focused coverage in the existing CVar guides when this page was prepared. They span asynchronous renderer work, exposure, post-processing/output, Beach and Bink rendering paths, CAS, and three Marvel-specific controls.

## How to read the evidence

The `CVarDump.txt` values below are captured values, not verified defaults or recommendations. The attachment does not identify its game build or capture method. Registry help is quoted or summarized as available; when help is blank, any name-based interpretation is explicitly marked as an inference. The Epic 5.9 reference is useful only where an exact upstream match exists and is not proof that Marvel Rivals uses the same implementation.

The local static scan targets Marvel Rivals Shipping build `1.1.4042190`. It found direct value-access candidates for the two `ref` entries, `r.AsyncCreateLightPrimitiveInteractions` and `r.CVarAbilityScopedEndAbility`. For the other 23 `var` entries, the saved scan found object-address/setup references but no direct value read. Absence from that scan does not prove that code never uses a value: indirect and non-RIP-relative access can be missed. Static references alone do not establish that the game accepts a startup override or what appears on screen.

## Editability and risk

The user's loader syntax can express every exact key above as a `name=value` line under `[Overrides]`. That confirms only that the supplied text format can represent the settings. It does not demonstrate that Marvel Rivals registers or accepts each override, that the setting survives game initialization, or that it reaches a live rendering/gameplay path. No runtime override acceptance test or controlled before/after test was performed.

Most entries are renderer, capture, or cinematic controls based on registry help or names. `r.CVarAbilityScopedEndAbility` has direct help describing ability lifecycle timing, and the two Spider Net entries are game-specific physics/gameplay names with no useful help. Avoid treating those three as cosmetic tuning. Their effects and any competitive, stability, or network implications have not been tested.
