# Replay memory and playback CVars

This guide covers 15 currently uncovered `demo.Memory.*` variables and 13 uncovered `demo.Playback.*` variables. Their names place them in replay-related namespaces, but that alone does not establish each setting’s function. Description fields reproduce community help where available or an exact-name Epic UE 5.9 reference; missing text is left unresolved. The community snapshot is not tagged with a build or capture method.

Build evidence comes from static address-reference scanning of Marvel Rivals Shipping build `1.1.4042190`. Direct-memory candidates do not distinguish reads, comparisons, and writes. CVar-object matches for `var` entries may be registration/setup code. None of these candidates prove a live playback path or that a config override is accepted.

## What can be concluded

- Available help describes asynchronous replay-world loading, replay chunk timing/compression, playback map loading, packet/raw-data behavior, and autonomous-view channel handling for some entries.
- Many memory and playback entries have no descriptive help in either the community data or Epic 5.9 reference. The document records those settings without assigning a guessed meaning.
- Captured values are not recommendations. A present `var`/`ref` registry row does not establish runtime editability, and static references are not a controlled behavior trace.

For context and full inventory, see the [community CVar registry](cvar-community-registry.md) and [build-specific static-analysis notes](EVIDENCE.md#build-specific-static-analysis).
