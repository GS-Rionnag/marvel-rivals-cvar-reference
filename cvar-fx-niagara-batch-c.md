# Niagara scheduling and async-trace CVars: FX batch C

This page covers the next 25 uncovered `fx.Niagara.*` variable rows in the preserved community registry. The help and captured values come from separate community attachments; the snapshot's build and collection method are unknown, so those values are observations, not verified defaults or recommendations. All entries below are typed `ref` in that registry. A `ref` label does not prove a user's startup `.ini` override is accepted.

## Evidence and editability limits

- The table uses exact names, types, and help from the community registry, captured values from its companion snapshot, and direct-reference candidate counts from the saved address scan for game build `1.1.4042190`.
- A direct-memory candidate means an instruction references the recorded CVar value address. It is static evidence of a value access, not proof that the branch executes in a match, that the value is changed by startup configuration, or that the visible outcome matches the help. Address-taking-only matches are not counted as value reads.
- The registry snapshot build and collection method are unknown. A captured value must not be treated as a verified game default. This matters for `CombineFX.EnablePerfOptimization`, whose help states platform-dependent defaults.
- No live console query, `.ini` override comparison, or in-game visual/performance test was performed for this batch. For scan methodology and build caveats, see [build-specific static-analysis notes](EVIDENCE.md#build-specific-static-analysis), [the community registry](cvar-community-registry.md), and [CVar override notes](cvar-overrides.md).
