# Global distance-field and distance-field AO CVars, batch A

This page documents 25 entries from the community `var`/`ref` registry. The settings cluster around distance-field ambient occlusion (DFAO) and the Global Distance Field (Global SDF): distance-field mesh processing, clipmap configuration, cache updates, and debug controls. The community descriptions are the most specific source for several names. A dump value is a captured setting, not a shipped default or recommendation.

## Variables

| Exact CVar | Type | Snapshot | What the available description says |
| --- | --- | ---: | --- |
| `r.AOAsyncBuildQueue` | int32 (`ref`) | `1` | Selects asynchronous construction of mesh distance-field volume data. This describes mesh-data building, not asynchronous Global SDF clipmap updates generally. |
| `r.AOAverageObjectsPerCullTile` | int32 (`ref`) | `512` | Preallocation estimate for distance-field object-culling structures. The registry warns that overestimation wastes memory and underestimation can cause buffer overflow/flicker. |
| `r.AOClearHistory` | int32 (`ref`) | `0` | No useful help text was supplied. The name suggests an AO-history control, but its exact trigger, lifetime, and effect are not established here. |
| `r.AOComputeShaderNormalCalculation` | int32 (`ref`) | `0` | Chooses the compute-shader version of distance-field normal calculation. The registry does not document quality/performance tradeoffs. |
| `r.AOGlobalDFClipmapDistanceExponent` | float (`ref`) | `2` | Exponent used with `r.AOInnerGlobalDFClipmapDistance` to derive clipmap sizes. The exact formula and supported range are not given. |
| `r.AOGlobalDFResolution` | int32 (`ref`) | `128` | Global Distance Field resolution. Registry help says higher values increase fidelity and also memory and composition cost; it does not specify dimensions or a supported range. |
| `r.AOGlobalDFStartDistance` | float (`ref`) | `100` | World-space cone-trace distance at which tracing switches from object distance fields to the Global SDF. Help says smaller values can make cone tracing faster, while the switch must be far enough out to mask the Global SDF's lower resolution. |
| `r.AOGlobalDistanceField` | int32 (`ref`) | `1` | Enables using the Global SDF to optimize occlusion cone traces. Help describes it as clipmaps made by compositing object distance fields as the viewer moves through the level. |
| `r.AOGlobalDistanceField.AverageCulledObjectsPerCell` | int32 (`var`) | `512` | Expected average objects per cull-grid cell, used to preallocate cull-grid memory. The registry does not specify the fallback or overflow behavior. |
| `r.AOGlobalDistanceField.CameraPositionVelocityOffsetDecay` | float (`ref`) | `0.7` | No useful help text was supplied. The variable name alone is insufficient to establish the offset, decay equation, or units. |
| `r.AOGlobalDistanceField.FastCameraMode` | int32 (`ref`) | `0` | Updates the Global SDF for fast camera movement with lower quality and faster updates so lighting can keep up. The exact speed threshold and quality change are unspecified. |
| `r.AOGlobalDistanceField.ForceRecacheForStreaming` | int32 (`ref`) | `0` | Debug/profiling control for forcing full clipmap updates when a clipmap is detected with pending streaming. This does not mean that all streaming events always trigger a recache. |
| `r.AOGlobalDistanceField.Heightfield` | int32 (`ref`) | `1` | Controls voxelizing a heightfield into the Global SDF. This is distinct from `r.AOGlobalDistanceFieldRepresentHeightfields`, which the registry describes as landscape representation. |
| `r.AOGlobalDistanceField.MinMeshSDFRadius` | float (`ref`) | `20` | Culls meshes below a world-space radius from the Global SDF. The exact radius definition and interaction with the voxel-relative threshold below are not specified. |
| `r.AOGlobalDistanceField.MinMeshSDFRadiusInVoxels` | float (`ref`) | `0.5` | Culls meshes below a radius measured in voxels from the Global SDF. The help does not explain how this combines with `MinMeshSDFRadius`. |
| `r.AOGlobalDistanceField.MipFactor` | int32 (`ref`) | `4` | Resolution divider for a distance-field clipmap mip map. No valid range or specific mip-selection formula is supplied. |
| `r.AOGlobalDistanceField.NumClipmaps` | int32 (`ref`) | `4` | Number of clipmaps in the Global SDF. The registry says values other than four are supported only by Lumen; do not assume that changing this is supported for the game's non-Lumen AO paths. |
| `r.AOGlobalDistanceField.OccupancyRatio` | float (`ref`) | `0.3` | Expected sparse Global SDF occupancy for page-atlas allocation. Help illustrates `0.25` as 25% filled and 75% empty. The snapshot is a different captured ratio, not proof of actual occupancy. |
| `r.AOGlobalDistanceField.RecacheClipmapsWithPendingStreaming` | int32 (`ref`) | `1` | Reads back clipmaps cached with incomplete mesh SDFs from streaming and recaches them on later frames. Registry help says this addresses inaccurate Global SDF around the camera after teleporting or loading a level. |
| `r.AOGlobalDistanceFieldCacheMostlyStaticSeparately` | int32 (`ref`) | `1` | Separately caches mostly static primitives and movable primitives, intended to reduce Global SDF update cost when a movable primitive changes. Help reports an extra 12 MB of volume textures; that cost is registry help, not a local measurement. |
| `r.AOGlobalDistanceFieldClipmapUpdatesPerFrame` | int32 (`ref`) | `2` | Number of clipmaps updated per frame. Help warns that values below two update the first clipmap only every other frame and can cause incorrect self-occlusion during movement. |
| `r.AOGlobalDistanceFieldDrawModifiedPrimitives` | int32 (`ref`) | `0` | Debug draw for primitive modifications (add, remove, transform update) that caused a Global SDF update; intended to help find expensive repeated updates. This is a visualization/debug control, not a culling-quality switch. |
| `r.AOGlobalDistanceFieldForceFullUpdate` | int32 (`ref`) | `0` | Forces a full Global SDF update every frame according to the help text. It is a costly-sounding debug/profiling behavior; no local benchmark quantifies its cost. |
| `r.AOGlobalDistanceFieldForceMovementUpdate` | int32 (`ref`) | `0` | Help says it forces an N-texel border on X, Y, and Z update each frame. `N`, the affected update path, and intended use are not explained. |
| `r.AOGlobalDistanceFieldForceUpdateOnce` | int32 (`ref`) | `0` | Forces one full Global SDF update. The precise reset/consumption behavior for the one-shot request is not documented in the available help. |

## Evidence and limits

- The names, types, community descriptions, and reference metadata come from [`console_vars.tsv`](https://discord.com/channels/1512820805615091712/1512825591529869383/1570970983353950322); the same information is indexed in the [community registry](cvar-community-registry.md). The spelling `r.AOGlobalDistanceFieldCacheMostlyStaticSeparately` is the exact registry name.
- Snapshot values come from [`CVarDump.txt`](https://discord.com/channels/1512820805615091712/1512825591529869383/1562934699502866452). The capture build, collection method, whether values are defaults, and whether they were user-overridden are unknown.
- Twenty-three of these 25 names have exact-name entries in the Epic Unreal Engine 5.9 reference; the two debug-oriented names `r.AOGlobalDistanceFieldDrawModifiedPrimitives` and `r.AOGlobalDistanceFieldForceMovementUpdate` do not. Epic descriptions/defaults are upstream context, not proof that Marvel's fork behaves identically. See each row in the community registry for the exact match/default. Where help is empty or only a placeholder, the meaning above is limited to other community text or explicitly marked as unknown.
- The saved local address scan [`build-4042190-cvar-address-hits.tsv`](EVIDENCE.md#evidence-artifacts-not-included) contains address-taken and direct-memory-candidate matches for these names in Shipping build 1.1.4042190. The scanner's direct-memory-candidate label does not by itself distinguish a value load from a store or establish that the path executes. This page does not claim a full control-flow trace for these 25 variables.
- The supplied loader syntax can express a value override, but no startup log or controlled in-game test here proves that this build accepts each override, that later initialization does not replace it, or that it changes rendered output. Values are not recommendations.
