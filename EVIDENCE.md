# Evidence, sources, and scope

This repository contains Markdown documentation only. It does not distribute game executables, mods, local configuration files, raw binary scans, source-dump files, scripts, or personal computer paths.

## Build-specific static analysis

Some guides report analysis of Marvel Rivals Shipping build 1.1.4042190. The raw executable, hashes, file inventories, and disassembly/address-scan exports are intentionally omitted. Those findings are static evidence only: a name string or address reference is not by itself proof of runtime registration, startup-config acceptance, or an in-game effect. Direct value reads are distinguished from object-address setup references where the available evidence permits.

The current focused guides report per-name static-operation or operand evidence for 67 of the 1,049 unresolved names (6.4%): 16 `demo.*`, 15 rendering, 4 `GAS.*`, 30 `Swift.*`, one BigHead boolean entry, and one `SpiderManager.*` flag. The `demo.*` subset has 26 backing-value read instructions. These remain partial static findings; branch reachability, full behavior, and accepted config values are not established. See the [demo read notes](cvar-demo-unresolved-value-reads.md), [rendering evidence notes](cvar-rendering-definition-evidence.md), [GAS call-path notes](cvar-gas-recording-and-spray.md), [Swift operand notes](cvar-swift-reference-operands.md), [BigHead scan detail](cvar-feature-residual.md#bighead-redirection-table-flag-scan-detail), and [SpiderManager branch detail](cvar-engine-evidence-b.md#spidermanager-web-trace-flag-branch-detail).

A final residual-family audit reviewed 90 unresolved `p.*` names against the preserved help, translation, and address-hit tables. It found no additional usable help or translations. The address scan has direct-memory candidates for 80 names, address-taking-only candidates for six, and no matching reference for four. Operand mnemonics alone do not show whether a reference reads, writes, initializes, or compares a value; existing Physics and Chaos guides remain the strongest available evidence for this group. A second pass over `Net.AsyncRep.*` found bool-load candidates for `AsyncReplicateCopy`, `AsyncReplicateShared`, `NetGUIDLock`, and `SmartLock`; byte comparisons for `NetPrioritySort`; and DWORD loads for `TaskPriority`. That table pass adds no control-flow evidence beyond the focused [async replication guide](cvar-async-replication-family.md), so it does not support new effect claims or change any definitions. These audit counts are scoped to the unresolved-family subsets and the saved scan for build 1.1.4042190.

## Method and reproducibility

The guides preserve the source of each claim and distinguish community help, upstream Unreal behavior, snapshots, and build-specific analysis. Raw scan exports and local analysis scripts are not included; readers should treat exact addresses as build-specific and revalidate them against the build they use.

## Coverage counts

The preserved community registry contains 8,973 distinct, case-sensitive names with a variable or reference entry. The focused guide tables now account for all 8,973 names (100% exact-name coverage). This is an inventory-coverage measure, not a claim that every behavior is understood: where supplied help is absent or ambiguous, the guides say so and leave the meaning unresolved. Three names also have dedicated prose analyses linked from the final registry-remainder guide.

These counts measure exact-name coverage of the preserved registry only. They do not establish registration in a particular Shipping build, effective values, startup override support, or complete behavioral understanding. Commands and candidates found only in snapshots, console objects, or upstream and binary comparisons fall outside the registry denominator.

Separately, the object-table-only audit lists 247 plausible setting-like console objects absent from the `var`/`ref` registry: 223 `ShowFlag.*` names and 24 other candidates. This is a separate evidence bucket from the outside-registry candidate count and may overlap it; the objects are not treated as confirmed CVars, and their variable-versus-command status remains unverified unless a guide states otherwise. See [the object-table-only candidate guide](cvar-object-only-plausible-candidates.md).

The focused candidate guides cover 135 distinct CVar-shaped names outside the registry. This count includes 55 snapshot-backed names, 28 names with an upstream Epic reference but no snapshot value, two names supported by a third-party config and Shipping strings, seven names found only in a separate public `userengine.ini`, 20 names from other public community configs/templates, three names from the additional public-source audit (`r.Shadow.RadiusThresholdRSM`, `r.DeferredDecals`, and `r.AllowParticles`), and 14 further names from a Steam config post. The 44 names supported only by public config/community sources remain unverified. Six other outside-registry candidates have embedded Shipping-string evidence for AudioLink or stereo-emulation names. Four visualization names appear in both graphics-candidate and source-comparison guides and count once. Two exact community spellings, `r.DepthofFieldQuality` and `r.Lumen.HardwareRaytracing`, are case variants of canonical registered names and are excluded from the distinct-candidate count. None of these names is thereby established as registered, accepted in startup configuration, or behaviorally verified.

The snapshot-only inventory contains 67 exact names, including the 55 with focused candidate notes. The other 12 lack exact matches in the preserved Epic reference and scanned Shipping string inventory. Their captured values remain inventory evidence, with game registration and runtime behavior unresolved. See [the snapshot-only inventory](cvar-snapshot-only.md).

The rendering cache guide records three candidate commands from nearby Shipping text. These fall outside both the registry-variable count and the variable-candidate count.
